# Roadmap: figma2aem → a FrameKit-style Figma → AEM product

FrameKit (a Figma → WordPress plugin by the same author)
turns a Figma frame into page-builder output through one pipeline:

> Figma (REST / plugin) → **build a manifest** (structure, roles, patterns,
> responsive, variants, tokens) → **gate** against the target's schema →
> **write** idempotently → **verify** (diff, parity, scores).

figma2aem already has the AEM end of that pipeline: packages, policies, DAM,
checks, preflight and the parity probe. It does not yet have FrameKit's front end,
which decides what each Figma layer becomes. Today a person writes `page.json`
by hand. The steps below close that gap, in order.

## What carries over, and what does not

| FrameKit | AEM equivalent in figma2aem | Status |
|---|---|---|
| Figma REST client, PAT/OAuth | `figma_client.py` (PAT) | ✅ (OAuth: later) |
| Manifest = builder-neutral tree + assets + warnings | `page.json` body + assets + `check` findings | ✅ hand-written; generated by step 2 |
| Output gate vs builder schema (`data/*.json`) | `check`: assets, style refs, LESS coverage; **add** component schema (allowed props per resource type) | 🟡 |
| Idempotent writes (asset identity by Figma key + node id) | stable style-ID lock; **add** `figma:fileKey/nodeId` in DAM metadata so re-exports update in place | 🟡 |
| Role inference (name 0.4, shape 0.4, extra 0.2) + reasons | **step 2** `propose`: Figma layer → AEM component + style keys, with a reason per guess | ⬜ |
| Patterns (card, tabs, accordion…) → builder widgets | pattern table against the AEM catalog: tabs → core Tabs, card → Teaser RTE v2, quote → container + image + text… (`docs/component-map.md` is the seed) | ⬜ |
| Role store / learned corrections by fingerprint | `mappings.json` per project: `fileKey:nodeId` and `component:<id>` → decision; accepted corrections reused | ⬜ |
| Responsive frames matched by name path | `verify` already matches layers by name; **add** reading tablet/mobile values from the frames into a token/LESS report | 🟡 |
| Variants → BEM classes, states → `:hover` / `:focus-visible` | Style System modifiers (`--secondary`, `--theme-warm`…) | 🟡 manual |
| Tokens: Variables → styles → Foundations page; coverage report | `clientlib --figma`: variables/styles → `design-system/` (tokens with responsive modes, spacing, grid, fonts, typography, variant mixins) + coverage report | 🟡 not yet run against a live file |
| Three-way diff (Figma / imported / live) + parity + scores | `verify/probe.mjs` (geometry + fonts); **add** copy/image diff and a per-page score table | 🟡 |
| MCP tools + AI proposals that a person accepts | **step 4** MCP tools: `layer_tree`, `propose`, `set_mapping`, `check`, `package`; AI output stays a proposal until accepted | ⬜ |
| Studio / admin UI | later; the CLI and the docs first | ⬜ |

Does **not** carry over: the builders' own CSS-cascade work, WordPress media
and post meta, child themes and SCSS writing, WooCommerce, licensing, and motion.
AEM needs Style System IDs, JCR docview packages, DAM assets and clientlibs
instead, which this tool already produces.

## Steps

1. **Done in this round.** Several pages per project, new pages, existing
   styles referenced by class, pre-package checks, server preflight, inventory,
   cropped fills, and probe font/auth fixes. Proven by reproducing a hand-built two-page server package file for file.
2. **`propose`: generate `page.json` from a Figma frame.** Walk the frame
   (REST); for each top-level section and nested instance:
   - Score candidate AEM components from the inventory: layer name, Figma
     component name (`componentMap`), structure (text + image → teaser,
     repeated siblings → grid, named tabs → Tabs), and fixed patterns.
   - Write a draft `page.json`, with every node carrying
     `"_reason": "name 'Teaser Grid' + 4 repeated card instances"` and
     `"_confidence": 0.82`.
   - Unknown layers become `TODO` nodes that `check` reports.
   - Accepted edits go to `mappings.json` and win over guesses on the next run.
3. **`tokens`: generate the token layer.** Figma variables (Enterprise) or
   styles become `tokens.less` custom properties plus the scoped tablet/mobile
   blocks. Report which design values have no token (FrameKit's
   "bound-unmatched").
4. **MCP server**, so Claude (or any MCP client) can drive steps 2–3. It reads
   the layer tree, proposes mappings, runs `check`, `package` and `preflight`.
   Every AI decision is marked `ai` and needs a person's accept, as in FrameKit.
5. **Verify v2.** Add text and image diffs to the geometry probe, and a score
   table per page and breakpoint stored in `build/`, so regressions show up
   between runs.
6. **Schema gate.** A per-resource-type list of allowed properties, read from
   component dialogs in AEM, so a typo like `fileRefrence` fails `check`
   instead of rendering nothing.
